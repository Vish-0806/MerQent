## 1. Executive Summary

Task 2.12 establishes a comprehensive, production-grade observability and telemetry foundation across the MerQent platform. As the system scales to manage high-value Private Equity deal engagements and confidential Post-Merger Integration (PMI) mandates, robust observability is critical to detect latency spikes, isolate dependency faults, track real-time error rates, and monitor traffic patterns without leaking sensitive enterprise data.

This implementation delivers:

1. **Structured Log Standardization with Automated Redaction**: `AppLogger` formats all application logs via Pino with standardized fields (`level`, `service`, `environment`, `correlationId`, `userId`, `tenantId`, `context`, `timestamp`, `message`), enriched automatically via `RequestContextService`. All parameters and error contexts are deeply sanitized through `sanitizeObject` to guarantee zero exposure of credentials, tokens, API keys, or deal parameters.
2. **Comprehensive Health & Readiness Architecture**: Disaggregated probes distinguishing process viability from dependency readiness:
   - **`GET /api/v1/health`**: Comprehensive report verifying PostgreSQL, Redis, and Storage backing dependencies.
   - **`GET /api/v1/health/live` (and `/liveness`)**: High-speed liveness probe validating event-loop responsiveness without dependency overhead.
   - **`GET /api/v1/health/ready` (and `/readiness`)**: Dependency readiness probe evaluating PostgreSQL and Redis, returning `200 OK` when healthy and setting `503 Service Unavailable` when critical dependencies fail.
3. **High-Performance In-Memory Application Metrics (`MetricsService`)**:
   - Zero-external-dependency registry capturing real-time request counts, in-flight gauges, latency percentiles (`p50`, `p90`, `p95`, `p99`), error rate percentages (`4xx` vs `5xx`), and dependency health.
   - Built-in route normalization prevents metric label cardinality explosions (parameterizes UUIDs and numeric IDs to `:id`).
4. **Dual-Format Metrics Endpoint (`GET /api/v1/metrics`)**:
   - Serves Prometheus / OpenMetrics text exposition format (`Content-Type: text/plain; version=0.0.4`) when queried by Prometheus scrapers or requested via `Accept: text/plain` / `?format=prometheus`.
   - Serves strongly-typed JSON (`MetricsSnapshot`) for internal diagnostics, CLI tools, and health dashboards.
5. **Unified Request Telemetry**: `LoggingInterceptor` captures execution duration and status codes across all API endpoints, updates metrics counters, and logs structured traces stamped with correlation IDs.

## 3. Endpoints & Metrics Introduced

### 3.1 Probes & Health Endpoints

| Endpoint | Method | Response Type | Status Codes | Description |
|:---|:---:|:---|:---:|:---|
| `/api/v1/health` | `GET` | `HealthResponse` | `200` | Full runtime health status with PostgreSQL, Redis, and Storage dependency map. |
| `/api/v1/health/live` | `GET` | `LivenessResponse` | `200` | Kubernetes/container liveness probe confirming Node event loop viability. |
| `/api/v1/health/liveness` | `GET` | `LivenessResponse` | `200` | Alias for `/health/live`. |
| `/api/v1/health/ready` | `GET` | `ReadinessResponse` | `200` / `503` | Dependency readiness probe. Returns 200 when PostgreSQL and Redis are ready; sets 503 if critical dependencies are down. |
| `/api/v1/health/readiness` | `GET` | `ReadinessResponse` | `200` / `503` | Alias for `/health/ready`. |

### 3.2 Metrics Endpoint (`GET /api/v1/metrics`)

- **JSON Format** (`Accept: application/json` or default):
  Exposes `MetricsSnapshot` containing request counters, latency percentiles (`p50`, `p90`, `p95`, `p99`), error rate percentages, and process memory metrics (`heapUsed`, `heapTotal`, `rss`).
- **Prometheus Format** (`Accept: text/plain` or `?format=prometheus`):
  Exposes standard Prometheus exposition format:
  ```text
  # HELP http_requests_total Total number of HTTP requests processed
  # TYPE http_requests_total counter
  http_requests_total{method="GET"} 42
  # HELP http_requests_in_flight Current in-flight HTTP requests
  # TYPE http_requests_in_flight gauge
  http_requests_in_flight 0
  # HELP http_request_duration_ms_histogram HTTP request latency distribution in ms
  # TYPE http_request_duration_ms_histogram histogram
  http_request_duration_ms_histogram_bucket{le="5"} 12
  http_request_duration_ms_histogram_bucket{le="25"} 35
  http_request_duration_ms_histogram_bucket{le="+Inf"} 42
  http_request_duration_ms_histogram_sum 840
  http_request_duration_ms_histogram_count 42
  # HELP dependency_status Dependency operational readiness (1=healthy, 0=unhealthy)
  # TYPE dependency_status gauge
  dependency_status{name="database"} 1
  dependency_status{name="redis"} 1
  dependency_status{name="storage"} 1
  # HELP process_uptime_seconds Total process uptime in seconds
  # TYPE process_uptime_seconds gauge
  process_uptime_seconds 45
  ```

## 6. Configuration & Production Deployment Considerations

### 6.1 Environment Configuration
The observability subsystem honors the following environment variables:

| Variable | Type | Default | Description |
|:---|:---:|:---:|:---|
| `LOG_LEVEL` | String | `info` (prod) / `debug` (dev) | Minimum log severity (`trace`, `debug`, `info`, `warn`, `error`). |
| `NODE_ENV` | String | `development` | Switches between `pino-pretty` (dev) and single-line structured JSON (prod). |
| `REDIS_HOST` / `REDIS_PORT` | String/Number | `localhost:6379` | Backing Redis instance probed for readiness. |
| `DATABASE_URL` | String | — | PostgreSQL connection string probed for readiness via `SELECT 1`. |

### 6.2 Kubernetes Deployment Manifest Configuration
Kubernetes container manifests should configure probes as follows:

```yaml
livenessProbe:
  httpGet:
    path: /api/v1/health/live
    port: 4000
  initialDelaySeconds: 5
  periodSeconds: 10
  timeoutSeconds: 2

readinessProbe:
  httpGet:
    path: /api/v1/health/ready
    port: 4000
  initialDelaySeconds: 10
  periodSeconds: 5
  timeoutSeconds: 3
  failureThreshold: 3
```

### 6.3 Prometheus Scrape Configuration
Prometheus servers or OpenTelemetry collectors can scrape metrics directly:

```yaml
scrape_configs:
  - job_name: 'merqent-api'
    metrics_path: '/api/v1/metrics'
    params:
      format: ['prometheus']
    static_configs:
      - targets: ['api.merqent.internal:4000']
```
