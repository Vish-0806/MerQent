## 1. Executive Summary

Task 2.11 establishes a robust, shared foundation of common backend infrastructure for the MerQent NestJS API (`apps/api`). As the platform prepares for extensive marketplace domain modules (projects, matching, shortlists, connections, messaging, taxonomies), this common layer ensures that:

1. **Request Context Is Universally Available**: Node's built-in `AsyncLocalStorage` safely binds and propagates request-scoped metadata (`correlationId`, `user`, `ip`, `userAgent`, `startTime`, and arbitrary key-value metadata) throughout async execution call-stacks without requiring prop-drilling or thread-unsafe state.
2. **Correlation IDs & User Context Propagate Seamlessly**: Every incoming HTTP request is assigned a deterministic or generated UUID correlation ID via `CorrelationIdMiddleware`, populated in the `x-correlation-id` response header, stored in the request context, and automatically stamped into service log statements. Upon successful JWT verification, `JwtAuthGuard` securely injects the authenticated `RequestUserContext` into the request context.
3. **Sensitive Information Is Strictly Redacted**: A dedicated `sanitizeObject` utility recursively scrubs sensitive keys (`password`, `token`, `secret`, `hash`, `credential`, `apiKey`) and masks credit cards / sensitive sequences before logging or telemetry serialization, preventing secret leaks.
4. **Standard Service & Pagination Conventions Are Codified**: An abstract `BaseService` provides consistent logging, correlation tracking, and caller/tenant introspection. A standardized `calculatePaginationOffsets` utility guarantees unified limit/page clamping and database `skip`/`take` calculation.
5. **Clean Dependency Injection via `@Global()` `CommonModule`**: `CommonModule` consolidates and exports all common providers (`RequestContextService`, `AppConfigService`, `CorrelationIdMiddleware`, `AllExceptionsFilter`, `TransformInterceptor`, `LoggingInterceptor`, `RolesGuard`, `PermissionsGuard`, `TenantGuard`), eliminating ad-hoc cross-module imports and providing clean service boundaries.

### 2.1 Request Context Service (`RequestContextService`)
- **Technology**: Node.js `node:async_hooks` via `AsyncLocalStorage<RequestContextData>`. Zero external packages needed.
- **Context Shape**:
  ```typescript
  export interface RequestContextData {
    correlationId: string;
    user?: RequestUserContext;
    ip?: string;
    userAgent?: string;
    startTime?: number;
    metadata?: Record<string, unknown>;
  }
  ```
- **Lifecycle**: Initialized per-request in `CorrelationIdMiddleware.use()`. The store is isolated to the asynchronous execution branch of each request, guaranteeing complete multi-tenant and multi-user concurrency safety.

### 2.2 JWT User Context Binding (`JwtAuthGuard`)
- In `JwtAuthGuard.canActivate()`, upon successful JWT verification and user resolution, the guard automatically calls:
  ```typescript
  this.requestContext?.setUser(request.user);
  ```
- As a result, subsequent downstream filters, interceptors, and domain services inheriting from `BaseService` can access `this.currentUser` or `requestContext.getUser()` without depending on Express `Request` objects.

### 2.3 Parameter Decorators
The common decorator library was completed with:
- `@CorrelationId()`: Extracts the correlation ID from the active request context or request headers.
- `@ClientIp()`: Extracts the proxy-safe client IP (handles `x-forwarded-for` arrays/lists and socket fallback).
- `@CurrentTenant()` / `@TenantId()`: Extracts the tenant ID from the authenticated user or route params.
- `@CurrentUser()`: Extracts the authenticated user or a specific user property.
- `@Roles(...)`: Assigns required roles for RBAC.
- `@RequirePermissions(...)`: Assigns required permissions for granular authorization.
- `@Public()`: Marks routes as public, bypassing authentication.

### 2.4 Secure Utilities
- **`sanitizeObject<T>(input: T, options?): T`**:
  Recursively traverses arrays and objects, replacing sensitive keys (`password`, `token`, `secret`, `hash`, `credential`, `apiKey`) with `[REDACTED]`. Creates a deep clone without mutating the caller's in-memory data structures.
- **`calculatePaginationOffsets({ page, limit }, defaultLimit, maxLimit)`**:
  Provides uniform page/limit validation, clamping limits to `[1, maxLimit]` (default 100), computing database-ready `skip` and `take`, and ensuring fallback defaults for `page` (1) and `limit` (20).

### 2.5 Base Service Pattern (`BaseService`)
- Subclassable abstract class `BaseService` provides:
  - Strongly-scoped `Logger` pre-configured with the service's class name.
  - Optional `RequestContextService` dependency injection.
  - `this.correlationId`: Returns the active correlation ID or falls back to `'no-correlation-id'`.
  - `this.currentUser`: Returns the active authenticated user from context.
  - `this.tenantId`: Returns the user's primary organization ID.
  - `this.logWithContext(level, message, contextData)`: Automatically injects correlation ID and sanitizes any contextual payloads before logging.

### 2.6 Centralized Configuration Access (`AppConfigService`)
- Strongly-typed wrapper around NestJS `@nestjs/config` `ConfigService`.
- Exposes typed getters for environment variables (`nodeEnv`, `port`, `jwtSecret`, `jwtExpiresIn`, `databaseUrl`, `redisUrl`, `corsOrigins`, etc.) and helper checks (`isProduction`, `isDevelopment`, `isTest`).

### 2.7 Global Module Registration (`CommonModule`)
- Decorated with `@Global()` in `apps/api/src/common/common.module.ts`.
- Exports:
  - `RequestContextService`
  - `AppConfigService`
  - `CorrelationIdMiddleware`
  - `TransformInterceptor`
  - `LoggingInterceptor`
  - `AllExceptionsFilter`
  - `RolesGuard`
  - `PermissionsGuard`
  - `TenantGuard`
- Imported once in `AppModule`, making all foundational services, guards, filters, and interceptors instantly available to any present or future marketplace module.

## 5. Security & Isolation Analysis

1. **Context Leakage Prevention**:
   - `RequestContextService` uses Node's standard `AsyncLocalStorage`, which garbage collects context records as soon as the associated asynchronous call stack terminates.
   - When requests complete, no residual context persists across incoming HTTP connections.
2. **Multi-Tenant Protection**:
   - `TenantGuard` and `BaseService.tenantId` cleanly decouple caller organization checks from raw query parameters, ensuring tenant verification occurs on authoritative token-derived context.
3. **Sensitive Data Sanitization**:
   - `BaseService.logWithContext` automatically applies `sanitizeObject` before emitting any structured log payloads, eliminating the risk of credentials or tokens reaching log aggregators.
4. **Header Forgery & Spoofing Defense**:
   - Correlation IDs received in `x-correlation-id` headers are validated; if malformed or omitted, a fresh RFC 4122 v4 UUID is generated.
