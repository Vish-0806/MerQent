## 1. Executive Summary

Task 2.R5 hardened authentication, tenant isolation, dynamic authorization, and degraded-mode resilience for MerQent's WebSocket (`/realtime`) subsystem. The server-side gateway now strictly validates tenant affiliations against PostgreSQL database ground truth rather than unverified client JWT claims, dynamically checks JWT expiration and account active status on every heartbeat, enforces tenant boundaries on project-scoped rooms (`project:<id>`), and provides explicit observability warnings when operating in in-memory degraded mode.

## 2. Confirmed Findings & Remediations

| ID | Vulnerability / Defect | Root Cause | Implemented Remediation | Verification Status |
|---|---|---|---|---|
| **R5.1** | Stale/Untrusted Firm ID in Token Payload | `user.firmMember?.firmId \|\| payload.firmId` allowed fallback to client token claim if DB firm membership was null. | Strictly derive `verifiedFirmId` from `user.firmMember?.firmId`. Non-admin users cannot bind to firm rooms without active DB firm membership. | Verified via unit test |
| **R5.2** | Silent Session Continuation Past JWT Expiry | Heartbeat handler only checked Redis token blacklist, not JWT signature or expiration. | Heartbeat handler now invokes `jwtService.verifyAsync(token, { secret })`. Expired tokens emit `WS_AUTHENTICATION_FAILED` and disconnect socket. | Verified via unit test |
| **R5.3** | Suspended/Deleted Users Remaining Connected | Active socket sessions did not re-verify DB account status during heartbeat. | Heartbeat handler queries database ground truth (`prisma.user.findUnique`). Accounts with non-ACTIVE status emit `ACCOUNT_SUSPENDED` and are disconnected. | Verified via unit test |
| **R5.4** | Project Room Join Authorization Void | `ROOM_PREFIX_PROJECT` was rejected by default without DB cross-tenant validation. | Async authorization verifies project ownership via `prisma.project.findUnique`. Only owning firm members or platform admins can join. | Verified via unit test |
| **R5.5** | Unobservable Degraded Mode During Redis Disconnect | `RealtimeService` emitted events in degraded in-memory mode without logging warnings. | Added `warnIfDegraded()` to log explicit warnings that cross-cluster broadcast is unavailable. | Verified via unit test |

## 3. Realtime Authorization Model

```
WebSocket Handshake:
  ├── Extract Token (auth.token or Authorization: Bearer <jwt>)
  ├── Verify JWT Signature & Expiry (jwtService.verifyAsync)
  ├── Verify Token Revocation (redisService.isTokenBlacklisted)
  ├── Ground-Truth User & Firm Verification (prisma.user.findUnique)
  ├── Enforce Max Concurrent Connections (WS_MAX_CONNECTIONS_PER_USER = 10)
  └── Auto-Subscribe to:
        ├── Private User Room: `user:<userId>`
        └── Verified Firm Room: `firm:<verifiedFirmId>` (if firm member)

Periodic Heartbeat (`ws:heartbeat`):
  ├── Re-verify JWT Expiry (jwtService.verifyAsync)
  ├── Re-verify Token Revocation (redisService.isTokenBlacklisted)
  ├── Re-verify DB User Status (ACTIVE status required)
  └── Acknowledge with timestamp

Room Subscription (`room:join`):
  ├── Rate limit check (max 30 events / 10s)
  ├── Payload validation (WsJoinRoomSchema)
  └── Server-side Authorization:
        ├── `user:<targetUserId>` -> allowed if targetUserId === user.id
        ├── `firm:<targetFirmId>` -> allowed if targetFirmId === user.firmId
        ├── `project:<targetProjectId>` -> allowed if project.firmId === user.firmId
        └── `PLATFORM_ADMIN` -> permitted to inspect any room
```

## 4. Degraded-Mode Guarantees

When Redis is disconnected or unavailable:
1. **Adapter Fallback:** `RedisIoAdapter` falls back to the in-memory Socket.IO adapter.
2. **Health Reporting:** `RealtimeService.checkHealth()` reports `{ status: 'degraded', adapter: 'redis' }`.
3. **Tenant Isolation Intact:** All room authorization checks, prefix validations, and token authentications remain 100% active. No cross-tenant data leaks can occur.
4. **Broadcast Scope Limitation:** Events emitted in degraded mode are delivered to connected sockets on the local API instance only; cross-node broadcast across multiple container instances is paused until Redis reconnects.
5. **Observability:** `RealtimeService` logs structured warning messages on every emit during degraded operation.
