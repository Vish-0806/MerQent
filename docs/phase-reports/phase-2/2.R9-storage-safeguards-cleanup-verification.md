## 1. Executive Summary

Task 2.R9 audited and reconciled MerQent's secure file storage subsystem, presigned URL architecture, malware-scanning lifecycle, tenant isolation, and abandoned upload cleanup workflows. All storage operations enforce strict tenant boundary partitioning (`tenants/<firmId>/...`), server-side object size validation (25 MB max limit enforced both pre-upload and post-upload via `headObject`), fail-closed ClamAV antivirus inspection, and atomic race-safe cleanup of abandoned uploads.

## 2. Storage Security Control Matrix

| Control Category | Implemented Mechanism | Security Guarantee | Verification Evidence |
|---|---|---|---|
| **Pre-Upload Validation** | `validateMimeAndExtension()`, `sanitizeFilename()` | Whitelist-only MIME types (`application/pdf`, docx, xlsx, etc.), directory traversal neutralization | Tested via `file-security.util.spec.ts` |
| **Server-Controlled Storage Keys** | `generateStorageKey()` | Path format `tenants/<firmId>/<folder>/<uuid>/<cleanName>`; prevents client storage key tampering | Tested via `files.service.spec.ts` |
| **Pre-Upload Presigned URL** | `S3StorageService.getPresignedUploadUrl()` | Short-lived (900s), scoped PUT URL with content-type restriction | Tested via `s3-storage.service.spec.ts` |
| **Initial File State** | `FileRecord.scanStatus = PENDING` | Files cannot be downloaded while in `PENDING` state | Tested via `files.service.spec.ts` |
| **Post-Upload Size Enforcement** | `storage.headObject()` in `confirmUpload()` | Validates actual S3 payload length. Oversized (> 25MB) or 0-byte objects are purged from S3 and rejected | Tested via `files.service.spec.ts` |
| **Malware Scanning Lifecycle** | `ClamAvMalwareScannerService` (`INSTREAM` protocol) | Scans raw stream; EICAR detected and quarantined; scanner outage fails closed; clean files marked `CLEAN` | Tested via `malware-scanner-real-daemon.integration.spec.ts` |
| **Download Authorization** | `FilesService.authorizeFileAccess()` | Tenant isolation enforced: user must own file or belong to tenant firm; admin oversight; cross-tenant denied | Tested via `security-tenant-isolation.integration.spec.ts` |
| **Download Clearance Gate** | `getDownloadUrl()` check: `scanStatus === CLEAN` | Non-clean files (`PENDING`, `INFECTED`) throw `ForbiddenException`; zero presigned download URLs issued | Tested via `files.service.spec.ts` |
| **Deletion Authorization** | `FilesService.authorizeFileModification()` | Only file owner, firm admin of tenant, or platform admin can delete file | Tested via `files.service.spec.ts` |
| **Abandoned Upload Cleanup** | `cleanupAbandonedUploads()` | Atomic conditional deletion (`deleteMany` where `status: PENDING` and `createdAt < cutoff`); race-safe against concurrent confirmation | Tested via `files.service.spec.ts` |

## 3. Malware Status Transition State Machine

```
Client Requests Upload
        │
        ▼
   [PENDING]  ───(Presigned PUT issued; FileRecord created)
        │
        ▼
 Client Uploads to S3 & Calls confirmUpload()
        │
        ├── HeadObject: Size > 25MB or 0B? ──► [PURGED & DELETED]
        │
        ├── ClamAV Daemon Inactive / Timed Out? ──► [REMAINS PENDING (Fails Closed)]
        │
        ├── ClamAV Scan: Threat Detected (EICAR)? ──► [INFECTED & PURGED] (HTTP 403)
        │
        └── ClamAV Scan: Clear (FOUND NO VIRUS)? ──► [CLEAN] (Downloadable)
```
