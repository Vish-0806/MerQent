## 4. Production Readiness & Signature Freshness Verification

### 4.1. Signature Update Mechanism
- **Freshclam Daemon**: The official `clamav/clamav:stable` container includes `freshclamd`, which automatically checks for database updates from `db.local.clamav.net` every 2 hours.
- **Production Configuration**: In `infrastructure/docker/docker-compose.prod.yml`, `CLAMAV_NO_FRESHCLAM: "false"` is configured, ensuring the updater daemon runs continuously in production.
- **Local Dev / Ephemeral CI**: Configured with `CLAMAV_NO_FRESHCLAM: "true"` to prevent IP rate-limiting against Cisco CDN servers during high-frequency build/test cycles.
- **Persistent Storage**: Configured `clamav_data:/var/lib/clamav` named volume across both development and production compose manifests. This prevents re-downloading ~200MB of signature definitions on container restarts.

### 4.2. Stale or Unavailable Definition Handling
- If `freshclam` cannot reach the Internet during an update cycle (e.g. DNS failure or outbound firewall), `clamd` continues to serve existing loaded signatures in memory without interruption.
- If signature databases are completely missing or corrupted, `clamd` fails to start and the container fails its health check (`clamdscan --ping 5`).
- The API's `/health/ready` check reports `dependencies.scanner: disconnected`, and upload confirmations strictly **fail closed** (keeping files in `PENDING`).

### 4.3. Resource Requirements & Limits
- **Daemon Memory**: ClamAV requires minimum **1.2GB – 1.5GB RAM** to hold the 3.6M signature database in memory.
- **Streaming Socket Timeout**: Configured `CLAMAV_TIMEOUT_MS: 10000` (10 seconds) with bounded per-file scanning.
- **Maximum File Size Ceiling**: Enforced at 25MB (`MAX_FILE_SIZE_BYTES = 26214400`). Streams exceeding 25MB trigger immediate socket destruction to prevent memory exhaustion.
- **Queue Retry Behavior**: The BullMQ queue (`file-processing-queue`) handles transient scanner failures with exponential backoff (3 retries). Files remain `PENDING` throughout retries and are never marked `CLEAN` until positive clearance.
