## 2. Audit Gate Architecture & `baselineTrackedAdvisories` Behavior

### Previous Behavior (at `f5ba30b`)
In the initial report generation script, `baselineTrackedAdvisories` was purely an informational metadata array written to the output JSON artifact. The script caught errors from `pnpm audit --json` and unconditionally executed `process.exit(0)`. While this prevented broken CI runs from pre-existing low/moderate devDependencies, it had an architectural weakness: **a newly introduced or worsening vulnerability would not cause CI to fail**.

### Hardened Behavior (Commits `8fcc2e9` & `aa71c6a`)
The script was refactored with a modular, exported evaluation engine: [`evaluateAuditGate(auditData, baselineTracked)`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/scripts/testing/audit-report.js#L18-L38):

```javascript
function evaluateAuditGate(auditData, baselineTracked = BASELINE_TRACKED_ADVISORIES) {
  const advisories = Object.values(auditData?.advisories || {});
  const metadata = auditData?.metadata || { vulnerabilities: {} };
  const baselineSet = new Set(baselineTracked);

  const newAdvisories = advisories.filter((a) => {
    const id = a.github_advisory_id || a.id;
    return !baselineSet.has(id);
  });

  const criticalAdvisories = advisories.filter((a) => a.severity === 'critical');
  const isPassing = newAdvisories.length === 0 && criticalAdvisories.length === 0;

  return {
    isPassing,
    advisories,
    newAdvisories,
    criticalAdvisories,
    metadata,
  };
}
```

### Behavioral Contract:
- **Zero Tolerance for Criticals**: Any Critical vulnerability causes the gate to fail immediately (`isPassing: false`), even if present in the tracked baseline list.
- **Fail-Closed on Untracked CVEs**: Any advisory whose ID is not explicitly registered in `BASELINE_TRACKED_ADVISORIES` triggers gate failure (`exit(1)`).
- **Explicit Visibility**: Active baseline advisories are printed with `[TRACKED BASELINE]` and severity levels. They are not masked or suppressed.

- **Severity**: Moderate (CVSS 6.1)
- **Installed Version**: `10.4.22` (latest on NestJS v10)

  ├── dependencies:
  │   └── @nestjs/core@10.4.22
  │       ├── @nestjs/platform-express@10.4.22 peer -> @nestjs/core@10.4.22
  │       ├── @nestjs/websockets@10.4.22 peer -> @nestjs/core@10.4.22

      └── @nestjs/testing@10.4.22 -> @nestjs/core@10.4.22

- **Applicability & Upstream Patch Availability**:
