## 1. Executive Summary & Verification Verdict

### Verdict: ACCEPTED & FULLY VERIFIED
The `/api/v1/metrics` operational endpoint has been secured against unauthenticated access, network eavesdropping, and privilege escalation while maintaining seamless integration with external scraping daemons (Prometheus, Datadog) and platform administrators.

### Core Architecture & Guarantees
1. **Default Deny**: All unauthenticated requests to `/api/v1/metrics` are denied with `HTTP 401 Unauthorized` and `ErrorCode.UNAUTHORIZED`.
2. **Dual-Pathway Authentication**:
   - **Machine-to-Machine (M2M) Scrapers**: Supports `x-metrics-key: <key>` header or `Authorization: Bearer <key>` matched against server-side `METRICS_SCRAPE_KEY` using constant-time byte comparison (`crypto.timingSafeEqual`) to prevent side-channel timing attacks.
   - **Platform Operators**: Supports standard user JWT access tokens via `Authorization: Bearer <jwt>`. Strictly enforces Role-Based Access Control requiring `UserRole.PLATFORM_ADMIN` (denying `PE_FIRM_ADMIN`, `PE_FIRM_MEMBER`, and `CONSULTANT_OPERATOR` with `HTTP 403 Forbidden`).
3. **Fail-Closed Monitoring Key Policy**: If `METRICS_SCRAPE_KEY` is undefined or empty on the server, scraper key authentication immediately fails closed with `HTTP 401 Unauthorized`.
4. **Zero Implicit Trust**: No client is granted access based on IP address, Docker subnet, or hostname.
5. **No Secret Leakage**: Scrape keys and tokens are never logged or exposed in responses.
6. **Public Probes Unaffected**: `/health` (liveness) and `/health/ready` (readiness) remain public and unauthenticated for Kubernetes/Docker ingress health checks.

## 2. Route Configuration & Access Control Design

### 2.1. Guard Flowchart
```
Incoming Request: GET /api/v1/metrics
               │
               ▼
   Has 'x-metrics-key' Header?
    ├─ YES ──► Is METRICS_SCRAPE_KEY configured?
    │           ├─ NO  ──► HTTP 401 (Fail-Closed)
    │           └─ YES ──► crypto.timingSafeEqual(header, configured)?
    │                       ├─ YES ──► HTTP 200 OK (Allowed: M2M Scraper)
    │                       └─ NO  ──► HTTP 401 Unauthorized
    │
    └─ NO ──► Has 'Authorization: Bearer <token>' Header?
               ├─ NO  ──► HTTP 401 Unauthorized
               └─ YES ──► Does Bearer match METRICS_SCRAPE_KEY?
                           ├─ YES ──► HTTP 200 OK (Allowed: Prometheus Bearer)
                           └─ NO  ──► Verify as User JWT
                                       ├─ Invalid / Expired / Blacklisted? ──► HTTP 401
                                       └─ Valid JWT:
                                           ├─ Role == PLATFORM_ADMIN ──► HTTP 200 OK
                                           └─ Role != PLATFORM_ADMIN ──► HTTP 403 Forbidden
```

### 2.2. Sensitive Metrics Exposed
Prior to access restriction, `/api/v1/metrics` exposed internal operational metrics without authentication:
- Detailed route counts and error rates (`http_requests_total`, `http_request_duration_seconds`).
- Memory distribution (`nodejs_heap_size_total_bytes`, `nodejs_heap_size_used_bytes`, `nodejs_external_memory_bytes`).
- Active tenant/user connection traffic patterns.
- Internal service uptime and system resource load.

Restricting access prevents reconnaissance attacks and infrastructure profiling.

## 3. Configuration Variables for Deployment

The following environment variables govern metrics endpoint protection:

| Environment Variable | Required | Default | Description |
| :--- | :---: | :--- | :--- |
| `METRICS_SCRAPE_KEY` | Recommended | `""` (Fail-Closed) | High-entropy secret key (min 32 characters recommended) shared with external monitoring scrapers (Prometheus, Datadog). If empty or omitted, M2M scraper authentication fails closed, requiring valid `PLATFORM_ADMIN` JWTs. |
| `JWT_ACCESS_SECRET` | Required | Pre-configured | Used to verify JWT signatures for administrative user access. |
| `REDIS_URL` | Required | Pre-configured | Used to check token revocation blacklist. |

### Scraper Configuration Examples

#### Prometheus (`prometheus.yml`):
```yaml
scrape_configs:
  - job_name: 'merqent-api'
    scrape_interval: 15s
    metrics_path: '/api/v1/metrics'
    params:
      format: ['prometheus']
    authorization:
      type: Bearer
      credentials: '<CONFIGURED_METRICS_SCRAPE_KEY>'
    static_configs:
      - targets: ['api:3001']
```

#### Datadog Agent (`openmetrics.d/conf.yaml`):
```yaml
init_config:
instances:
  - openmetrics_endpoint: http://api:3001/api/v1/metrics?format=prometheus
    extra_headers:
      x-metrics-key: '<CONFIGURED_METRICS_SCRAPE_KEY>'
    namespace: merqent
```
