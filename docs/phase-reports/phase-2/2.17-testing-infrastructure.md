## 2. Testing Architecture & Standardization

### 2.1 Test Classification & Conventions
Testing across the monorepo is organized into four standardized tiers:

| Tier | File Pattern | Execution Scope | Environment / Isolation |
| :--- | :--- | :--- | :--- |
| **Unit Tests** | `*.spec.ts`, `*.spec.tsx` | Pure functions, domain services, controllers, guards, filters, interceptors | In-memory, mocked dependencies, isolated runtime |
| **Integration Tests** | `src/test-integration/*.integration.spec.ts` | Multi-module coordination (e.g. upload -> queue -> malware scan -> download) | High-fidelity test doubles for DB, Redis, S3, scanner |
| **End-to-End Tests** | `src/test-e2e/*.e2e.spec.ts` | Real HTTP server on ephemeral OS ports (`app.listen(0)`), header propagation | Ephemeral HTTP server, simulated client requests |
| **Smoke Probes** | `tests/smoke/run-smoke-tests.js` | Zero-dependency deployment gate verifying monorepo exports, schemas & paths | Pure Node.js CLI returning exit code 0 or 1 |

### 3.1 Security & Determinism Guarantees
- **No Production Secrets**: All JWT secrets, storage endpoints, and database connection strings use synthetic test identifiers (e.g. `test-secret-min-32-chars-length`, `https://s3.mock.merqent.test`).
- **Deterministic State Isolation**: Mocks feature synchronous and asynchronous reset hooks (`mock.reset()`, `mockRedis._store.clear()`) ensuring tests run independently in any order without state leakage.
- **Fail-Closed Verification**: The mock malware scanner (`createMockMalwareScanner`) supports dynamic status toggling (`setLive(false)` and `setInfected(true)`) to verify security fail-closed semantics.

## 4. Cross-Module Integration Test Coverage

Three dedicated integration test suites were established in `apps/api/src/test-integration/` to exercise critical cross-module security and infrastructure interactions:

### 4.1 Security & Multi-Tenant Isolation (`security-tenant-isolation.integration.spec.ts`)
- **Tenant File Download Boundary**: Verifies that a member of Firm Two receives `ForbiddenException` when attempting to access a document belonging to Firm One.
- **Tenant File Deletion Boundary**: Verifies that non-admin and cross-tenant users are denied permission to delete another tenant's files.
- **WebSocket Room Authorization**: Verifies that client connection handshake and room subscription logic rejects unauthorized room joins (`firm:firmTwo` by Firm One user) with `WS_ROOM_JOIN_DENIED`.
- **Token Revocation Propagation**: Verifies that blacklisting an access token in Redis causes active WebSocket heartbeats to disconnect revoked sessions immediately.
- **Worker Storage Key Tampering**: Verifies that background worker jobs reject execution when the queued payload `storageKey` diverges from database ground truth.

### 4.2 File Storage Pipeline (`file-storage-pipeline.integration.spec.ts`)
- **Full Clean Pipeline**: Tests end-to-end progression: Presigned Upload -> Upload Confirmation -> BullMQ Malware Scan -> DB Clearance (`CLEAN`) -> Presigned Download URL issuance.
- **Infected File Quarantine**: Tests that malware detection by the background worker purges the object from storage, updates DB status to `INFECTED`, and subsequent download attempts fail closed with `ForbiddenException`.
- **Inactive Scanner Fail-Closed**: Tests that an unattached or unresponsive scanning daemon leaves the file in `PENDING` state and rejects downloads.

### 4.3 Realtime Clustering & In-Memory Fallback (`realtime-clustering-fallback.integration.spec.ts`)
- **Clustered Event Delivery**: Verifies that `RealtimeService.emitToFirm` and `emitToUser` route payloads to the correct Socket.IO cluster room.
- **Degraded In-Memory Mode**: Verifies that when Redis Pub/Sub fails or disconnects, the Socket.IO adapter status gracefully reports `degraded` in-memory mode without terminating connections.

## 5. End-to-End (E2E) & Automated Smoke Test Infrastructure

### 5.1 API E2E Workflows (`apps/api/src/test-e2e/api-flows.e2e.spec.ts`)
Executes an actual NestJS application instance bound to an ephemeral HTTP port (`app.listen(0)`):
- **Health Probes**: `GET /health` and `GET /health/ready` return 200 OK with runtime dependencies status and timestamp.
- **Correlation ID Propagation**: Verifies that custom `x-correlation-id` request headers pass through to HTTP response headers.
- **Weak Password Rejection**: Verifies that `POST /auth/register` returns `400 Bad Request` with structured `VALIDATION_ERROR` error code.
- **Unverified / Non-Existent User Login**: Verifies that `POST /auth/login` returns `401 Unauthorized` without leaking account existence.
- **Missing Token Rejection**: Verifies that protected routes (`GET /auth/me`) reject unauthenticated requests.
- **Blacklisted Token Rejection**: Verifies that revoked JWT tokens are rejected with `TOKEN_EXPIRED`.
- **Browser Security Headers**: Verifies `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY` on all responses.

### 5.2 Automated Smoke Test Runner (`tests/smoke/run-smoke-tests.js`)
A lightweight, zero-network CLI runner that executes across 6 categories:
1. Monorepo architecture & workspace package configuration
2. Shared package exports & Zod validation schema contracts
3. Environment variables & production secret prevention
4. Backend API controllers, services & gateway modules
5. Web frontend layout, authentication & API client utilities
6. Test utilities, factories, integration suites & E2E harnesses
