## 1. Objective

The objective of Task 2.3 was to establish a production-grade, highly aesthetic, accessible, and responsive Next.js frontend foundation for MerQent without prematurely implementing marketplace business logic or authentication flows.

Specific objectives:
1. Reconcile and extend `apps/web` with the approved technology stack (Next.js 14 App Router, TypeScript, Tailwind CSS, Radix UI).
2. Establish the MerQent design system baseline: typography, dark-theme surface tokens, semantic states, accessible focus indicators, and custom scrollbars suitable for Private Equity and M&A integration leaders.
3. Deliver foundational UI primitives: `Button`, `Input`, `Card`, `Badge`, `Dialog`, `DropdownMenu`, `Tooltip`, and `Separator`.
4. Establish global layout architecture: responsive sticky `Header`, institutional `Footer`, `Container` wrapper, and accessible `MobileNav`.
5. Deliver core foundation pages: high-impact `page.tsx` landing page, route `error.tsx` boundary, accessible `not-found.tsx` 404 handler, and animated `loading.tsx` UI.
6. Provide a typed, centralized API client foundation (`lib/api-client.ts`) utilizing `NEXT_PUBLIC_API_URL` with standardized error wrapping (`ApiClientError`) and auth token attachment hooks.
7. Verify all linting, typechecking, tests (including new Jest suites for web), and Next.js development server startup.

## 5. Layout Architecture

The layout architecture establishes universal structure across all viewports:

- **Root Layout (`apps/web/app/layout.tsx`):** Wraps all views in `TooltipProvider`, sets dark canvas, injects Next.js 14 metadata and separate `viewport` configuration, and frames the viewport between `Header` and `Footer`.
- **Header (`apps/web/components/layout/header.tsx`):** Sticky, scroll-responsive navigation bar featuring the MerQent brand logo with PMI badge, desktop navigation links, Solutions dropdown menu, action buttons, and mobile navigation trigger.
- **Mobile Navigation (`apps/web/components/layout/mobile-nav.tsx`):** Accessible overlay sheet providing full navigation access on mobile devices with keyboard Escape listeners and body scroll lock.
- **Institutional Footer (`apps/web/components/layout/footer.tsx`):** 5-column layout detailing Governed Taxonomies, Solutions for PE Sponsors & PMI Operators, and Security & Compliance trust marks (SOC 2, Dual-Token JWT, Row-Level Security).
- **Container (`apps/web/components/layout/container.tsx`):** Standardized responsive width constraints (`narrow`: max-w-4xl, `default`: max-w-7xl, `wide`: max-w-[1400px]).

## 6. API Client Architecture

The typed client in [`apps/web/lib/api-client.ts`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/apps/web/lib/api-client.ts):
- Respects `NEXT_PUBLIC_API_URL` (defaulting safely to `http://localhost:4000/api/v1`).
- Provides type-safe verbs: `get<T>`, `post<T>`, `put<T>`, `patch<T>`, `delete<T>`.
- Automatically sets standard JSON request headers (`Content-Type: application/json`, `Accept: application/json`).
- Serializes URL query parameters cleanly.
- Implements `ApiClientError` capturing HTTP status codes, structured server error payloads, and normalized error message strings (including array messages from NestJS `ValidationPipe`).
- Exposes `setAuthToken(token)` and `getAuthToken()` as non-intrusive foundation hooks for Phase 2 authentication without implementing business workflows prematurely.
