## 3. Environment Architecture

MerQent enforces a tiered, environment-specific configuration architecture distinguishing three runtime tiers:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        MerQent Environment Hierarchy                  │
└────────────────────────────────────────────────────────────────────────┘
            │
            ├── Development (Local Workstation)
            │   ├── File: .env (gitignored)
            │   ├── Infrastructure: Docker Compose (PostgreSQL 16, Redis, MinIO)
            │   ├── Logging: debug / pretty
            │   └── Security: Local non-production secrets, CORS allows localhost
            │
            ├── Test / CI
            │   ├── File: Injected via CI environment runners
            │   ├── Infrastructure: Ephemeral test containers
            │   ├── Logging: error / silent
            │   └── Security: Ephemeral test tokens, strict schema validation
            │
            └── Production
                ├── File: Injected via Cloud Secret Manager (AWS Secrets Manager / Vault)
                ├── Infrastructure: AWS Aurora Serverless v2 PostgreSQL, ElastiCache, S3
                ├── Logging: info / structured JSON (Pino)
                └── Security: High-entropy secrets, strict SSL, CORS restricted to domains
```

### Configuration Ownership Boundaries

1. **`apps/api` (Server-Side Configuration):**
   - Governed by [`apps/api/src/config/env.schema.ts`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/apps/api/src/config/env.schema.ts).
   - Validates all sensitive infrastructure credentials (`DATABASE_URL`, `JWT_SECRET`, `REDIS_URL`, `AWS_SECRET_ACCESS_KEY`, `AI_PROVIDER_API_KEY`).
   - Managed through NestJS `ConfigModule` and accessed only via typed dependency injection.
2. **`apps/web` (Client-Side Configuration):**
   - Governed by [`apps/web/config/env.ts`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/apps/web/config/env.ts).
   - Whitelist restricted exclusively to `NEXT_PUBLIC_*` variables (`NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_WS_URL`).
   - Prevents build-time leakage of database strings, secrets, or server tokens into browser JS bundles.
3. **`packages/config` (Universal Constants):**
   - Contains immutable architectural tokens, domain limits, and conventions (e.g., token lifetimes, max upload sizes, pagination defaults) that do not vary by environment.

## 5. Docker Infrastructure

The local infrastructure definition in [`infrastructure/docker/docker-compose.yml`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/infrastructure/docker/docker-compose.yml) orchestrates the three services required for local development:

```yaml
version: "3.8"

services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: merqent-postgres
    ports:
      - "${POSTGRES_PORT:-5432}:5432"
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-merqent_user}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-merqent_password}
      POSTGRES_DB: ${POSTGRES_DB:-merqent_db}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-merqent_user} -d ${POSTGRES_DB:-merqent_db}"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - merqent-network

  redis:
    image: redis:7-alpine
    container_name: merqent-redis
    ports:
      - "${REDIS_PORT:-6379}:6379"
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - merqent-network

  minio:
    image: minio/minio:RELEASE.2024-05-10T01-41-38Z
    container_name: merqent-minio
    ports:
      - "${MINIO_PORT:-9000}:9000"
      - "${MINIO_CONSOLE_PORT:-9001}:9001"
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER:-minioadmin}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD:-minioadmin}
    volumes:
      - minio_data:/data
    command: server /data --console-address ":9001"
    healthcheck:
      test: ["CMD", "mc", "ready", "local"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: unless-stopped
    networks:
      - merqent-network

volumes:
  postgres_data:
  redis_data:
  minio_data:

networks:
  merqent-network:
    driver: bridge
```

### Key Infrastructure Design Principles:
1. **Configurable Ports:** Port bindings use `${SERVICE_PORT:-default}` pattern, allowing developers to change host ports via `.env` without modifying Compose files.
2. **Persistent Named Volumes:** Data persists across container restarts and updates.
3. **Dedicated Bridge Network:** Container-to-container communication is isolated within `merqent-network`.
4. **Verified Config Syntax:** Validated via `docker compose -f infrastructure/docker/docker-compose.yml config`.

## 6. PostgreSQL

PostgreSQL 16 is the single primary relational store for MerQent (governed by [ADR-003](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-003-database.md)).
- **Version:** PostgreSQL 16 (running via `pgvector/pgvector:pg16`).
- **Extensions:** `pgvector` (vector embedding storage & similarity search), `pg_trgm` (trigram fuzzy text matching), and `uuid-ossp` (UUID v4 generation).
- **Persistence:** Volume `postgres_data` mounted at `/var/lib/postgresql/data`.
- **Health Check:** `pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}` with 10s interval, 5s timeout, 5 retries.

## 7. pgvector

In strict adherence to Phase 1 architecture ([ADR-003](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-003-database.md) and [ADR-007](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-007-search.md)):
- `pgvector` is embedded directly within the primary PostgreSQL database image (`pgvector/pgvector:pg16`).
- **Zero Secondary Vector Databases:** Pinecone, Weaviate, Milvus, and Qdrant are intentionally omitted to avoid cross-network ETL pipelines, eventual consistency lags, and duplicate storage costs.
- **Schema Compatibility:** Prisma schema enables `postgresqlExtensions = [pgvector(map: "vector")]`.
- **Dimension Standard:** 1536-dimensional vectors for semantic consultant profile and project requirement matching.

## 8. Redis Decision

**Decision:** Retained and justified.

### Justification:
In accordance with [ADR-005](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-005-authentication.md) and [ADR-008](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-008-realtime.md):
1. **Socket.IO Real-Time Scaling:** WebSockets require Redis pub/sub adapter (`@socket.io/redis-adapter`) to support horizontal scaling across multi-instance API deployments.
2. **Refresh Token Revocation Denylist:** Sub-millisecond lookup of revoked JWT refresh tokens prior to DB persistence sync.
3. **Background Job Queue:** Asynchronous job processing (e.g., email dispatch, ClamAV malware scan triggers, embedding generation) via BullMQ.
4. **Lightweight Alpine Footprint:** `redis:7-alpine` adds less than 35MB overhead to local developer machines.

## 9. Object Storage Decision

**Decision:** MinIO retained as local S3 emulator.

### Justification:
In accordance with [ADR-009](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/docs/decisions/ADR-009-storage.md):
1. **S3 Protocol Parity:** The production environment uses AWS S3 with presigned upload/download URLs (TTL <= 15m). MinIO provides bit-for-bit API compatibility for local development without requiring live AWS credentials or incurring AWS billable usage.
2. **Document Workflows:** Necessary for developing resume uploads, verification certificates, project exhibits, and message attachments.
3. **No Direct Upload Through API:** Preserves the architectural mandate that files flow directly from browser/client to object store via signed URLs.

## 21. Problems Encountered

1. **Host Port 5432 Occupied by Standalone Windows Service:**
   - Inspection of local networking revealed that local port 5432 was already bound by an existing Windows service (`postgresql-x64-18`).
   - If Docker Compose hardcoded `5432:5432`, starting the Compose container would produce an immediate `bind: address already in use` error on developer machines with local PostgreSQL installed.
2. **Missing Docker Daemon on Host Machine:**
   - Docker Desktop was installed on the workstation but the background daemon was not currently running. Unchecked setup scripts would fail abruptly during `docker compose up`.
3. **Secret Masking Requirement:**
   - Standard Node scripts logging environment configuration risk printing plaintext database connection strings and passwords to the console or CI log files.

---

## 22. Resolutions

1. **Parameterizable Compose Ports:**
   - Updated `docker-compose.yml` to use `${POSTGRES_PORT:-5432}:5432`. Developers with conflicting local PostgreSQL instances can simply set `POSTGRES_PORT=5433` in `.env` without modifying repository files.
2. **Graceful Docker Daemon Detection:**
   - Updated `setup-dev.ps1` and `setup-dev.sh` to check `docker info 2>&1` before attempting to invoke Compose. If the daemon is inactive, the scripts output helpful setup guidance without crashing the developer setup workflow.
3. **Safe Credential Masking in Validation CLI:**
   - In [`scripts/validate-env.js`](file:///c:/Users/Vishal%20S%20Naik/MyProjects/MerQent/scripts/validate-env.js), the database connection string is parsed as a URL, the password is replaced with `****`, and only the sanitized URI is printed to stdout.
