## 1. Executive Summary

Task 2.14 implements a secure, production-grade file storage foundation for the MerQent platform using MinIO and S3-compatible object storage. In Private Equity and Post-Merger Integration (PMI) deal environments, diligence documentation, financial models, corporate filings, and compliance artefacts represent high-value, confidential assets. Permitting arbitrary file uploads or weak authorization boundaries introduces extreme risk of data leakage, tenant crossover, server-side request forgery (SSRF), and remote exploitation.

This implementation delivers an isolated, private-bucket storage architecture governed by server-side authorization:

1. **Dedicated S3/MinIO Storage Integration (`S3StorageService`)**: Connects to S3-compatible endpoints (MinIO in local/dev environments and AWS S3 in production) via `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`. Implements typed configuration with path-style access support, validating all bucket and credential parameters via environment variables. Storage secrets are strictly confined to the backend and never exposed to the frontend.
2. **Strict Server-Controlled Storage Keys & Multi-Tenant Isolation**: Clients cannot choose storage keys or directory paths. Storage keys are generated exclusively server-side using secure UUIDs and partitioned by tenant (`tenants/{firmId}/...`) or independent consultant (`users/{userId}/...`). Cross-tenant access is strictly prohibited with explicit tenant ownership checks.
3. **Multi-Layer Upload Validation**: Upload requests are checked against a strict MIME type allowlist (PDF, Word, Excel, CSV, TXT, PNG, JPEG, WEBP) and validated for matching file extensions. Request filenames are sanitized against path traversal (`..`), directory separators, null bytes, and control characters. A hard size limit (25 MB) is enforced before issuance of upload URLs and re-verified via `HeadObject` upon upload confirmation.
4. **Explicit Malware Scanning Integration Boundary**: Implemented `BoundaryMalwareScannerService` defining an explicit boundary for antivirus inspection. Reflecting the prompt's mandate to never claim files are scanned without an active scanner daemon, the boundary explicitly reports `isLive = false` and provides diagnostic status logging without deceptive security assertions.
5. **Metadata Persistence & Abandoned Upload Lifecycle**: Reuses the pre-existing database-backed `FileRecord` table in Prisma without unnecessary schema modifications. Unconfirmed or abandoned uploads older than a configurable threshold (e.g., 24 hours) are cleanly pruned via `cleanupAbandonedUploads` without deleting unrelated tenant data.
6. **Observability & Health Readiness Probes**: Storage availability is verified via `checkHealth` (executing `HeadBucketCommand`). Integrated directly into `/health` and `/health/ready` endpoints in `AppController`, correctly returning `503 Service Unavailable` when storage is disconnected. Sensitive presigned URLs, credentials, and file contents are never logged.

### 2.1 Multi-Tenant Storage Partitioning

Object storage keys are generated server-side using the following strict layout:

- **PE Firm Tenant Documents:** `tenants/{firmId}/{purpose}/{fileRecordId}/{safeName}`
- **Independent Consultant / User Documents:** `users/{userId}/{purpose}/{fileRecordId}/{safeName}`

Clients cannot alter or choose the path prefix. Any attempt by a user from `firm-blackstone` to access, confirm, download, or delete an object belonging to `firm-apollo` is rejected with `403 Forbidden` (`ErrorCode.FILE_ACCESS_DENIED` or `ErrorCode.FORBIDDEN`). Platform administrators (`PLATFORM_ADMIN`) are granted audited operational access for system maintenance.

### 2.2 Upload Constraints & Sanitization Rules

- **Allowed MIME Types & Extensions:**
  - `application/pdf` (`.pdf`)
  - `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (`.docx`)
  - `application/msword` (`.doc`)
  - `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (`.xlsx`)
  - `application/vnd.ms-excel` (`.xls`)
  - `text/csv` (`.csv`)
  - `text/plain` (`.txt`)
  - `image/png` (`.png`)
  - `image/jpeg` (`.jpg`, `.jpeg`)
  - `image/webp` (`.webp`)
- **Sanitization Logic:**
  - Rejects null bytes (`\0`), path traversal tokens (`..`), path separators (`/`, `\`), and control characters.
  - Strips leading and trailing dots and spaces.
  - Falls back to `unnamed_document` if the filename becomes empty after stripping unsafe characters.
  - Generates unique server-side storage paths so duplicate filenames cannot overwrite existing files.
- **Maximum File Size:** `26,214,400` bytes (25 MB). Both declared size and actual S3 `ContentLength` (via `HeadObject`) are validated before confirmation.

### 2.3 Explicit Malware Scanning Boundary

The prompt establishes that files must never be claimed to be scanned unless a real scanner is configured and verified.
`BoundaryMalwareScannerService` provides:
- An explicit declaration `isLive = false`.
- Diagnostic notices logged when scan boundaries are evaluated.
- Transparent reporting of scan statuses: files can transition to `CLEAN`, `INFECTED`, or `FAILED`.
- Quarantine enforcement: Any file marked `INFECTED` is quarantined, its S3 storage object is immediately deleted, and subsequent download requests are rejected with `403 Forbidden` (`ErrorCode.MALWARE_DETECTED`).

## 3. Configuration & Environment Variables

Storage configuration is managed via typed settings in `AppConfigService` and validated against environment variables:

| Variable | Type | Default | Purpose |
| :--- | :--- | :--- | :--- |
| `STORAGE_DRIVER` | `string` | `s3` | Object storage provider (`s3` / `minio`). |
| `STORAGE_ENDPOINT` | `string` | `http://localhost:9000` | S3 endpoint URL (MinIO local or AWS S3 endpoint). |
| `STORAGE_REGION` | `string` | `us-east-1` | S3 signing region. |
| `STORAGE_BUCKET` | `string` | `merqent-secure-documents` | Private bucket name for document storage. |
| `STORAGE_ACCESS_KEY` | `string` | (required in dev) | S3 access key ID (never exposed to frontend). |
| `STORAGE_SECRET_KEY` | `string` | (required in dev) | S3 secret access key (never committed or exposed). |
| `STORAGE_PRESIGNED_EXPIRATION_SECONDS` | `number` | `900` | Lifetime in seconds for presigned upload/download URLs (15 mins). |
| `MALWARE_SCANNER_ENABLED` | `boolean` | `false` | Explicit flag controlling live daemon scanning. |

### 5.2 Storage & File Test Coverage Details

- **Path Traversal & Unsafe Filenames:**
  - Tested `../../etc/passwd`, `..\\..\\Windows\\System32\\cmd.exe`, `..\file.pdf`, null-byte injections (`file.pdf\0.exe`), and control characters. All traversal tokens stripped; sanitized paths validated.
- **MIME Type & Extension Mismatches:**
  - Tested spoofed extensions (e.g. `.exe` with `application/pdf`, `.pdf` with `application/x-msdownload`). Rejected with `400 Bad Request` (`ErrorCode.INVALID_FILE_TYPE`).
- **Oversized Uploads:**
  - Tested uploads exceeding 25 MB (`26,214,401` bytes). Rejected at presign phase and re-verified at confirmation phase with `400 Bad Request` (`ErrorCode.FILE_TOO_LARGE`).
- **Multi-Tenant Access Isolation:**
  - Tested cross-tenant download, metadata, and deletion attempts (e.g. `firm-blackstone` attempting to read `firm-apollo` file). Rejected with `403 Forbidden` (`ErrorCode.FILE_ACCESS_DENIED`).
  - Tested consultant operator attempting to access PE firm tenant files outside their scope. Rejected with `403 Forbidden`.
  - Tested platform administrator authorized access. Permitted and logged.
- **Malware Boundary & Quarantine:**
  - Tested handling when scanner marks a file `INFECTED`. Object is deleted from storage, database status marked `INFECTED`, and download attempts rejected with `403 Forbidden` (`ErrorCode.MALWARE_DETECTED`).
- **Storage Disconnection & Readiness:**
  - Tested `/health/ready` when MinIO/S3 is unreachable. HTTP response returns `503 Service Unavailable` with `storageStatus: 'disconnected'`.
