## 8. Issues Encountered & Resolved

1. **Host Port Collision with Windows Native PostgreSQL 18:**
   - *Issue:* A native Windows service (`postgresql-x64-18`) was running on port 5432, intercepting `localhost:5432` traffic and causing authentication failures (`P1000`).
   - *Resolution:* Configured `POSTGRES_PORT=5433` in `.env` and `infrastructure/docker/docker-compose.yml`, updating `DATABASE_URL` to route directly to containerized PostgreSQL 16 + pgvector on port 5433.
2. **Non-Interactive Migration Execution:**
   - *Issue:* `prisma migrate dev` detected a non-interactive shell in headless execution and aborted.
   - *Resolution:* Baseline migration was cleanly generated via `prisma migrate diff` into `prisma/migrations/20261009185000_init/migration.sql`, registered with `migration_lock.toml`, and applied with `prisma migrate deploy`.
3. **PowerShell UTF-8 BOM on Windows:**
   - *Issue:* PowerShell 5.1 default `Out-File -Encoding utf8` prepends a UTF-8 Byte Order Mark (`\u{feff}`) which PostgreSQL parser rejects.
   - *Resolution:* Stripped the BOM to ensure clean UTF-8 encoding across all migration and script files.
