## 3. Database Architecture & Extension Dependencies

1. **PostgreSQL Version:** PostgreSQL 16.x
2. **Required Extensions:**
   - `vector` (`pgvector` 0.5.1+): Required for storing 1536-dimensional OpenAI embeddings in `consultant_profiles.embedding` and `projects.embedding`.
   - `pg_trgm`: Required for fuzzy trigram text search on consultant names, bios, and PMI skill taxonomies.
   - `uuid-ossp`: Required for `uuid_generate_v4()` primary key defaults across all models.
3. **Migration Consistency:**
   - Schema state is tracked in `_prisma_migrations`. Restorations must preserve migration checksums and application timestamps to allow future `prisma migrate deploy` executions.

## 5. Production Database Recovery Runbook

### A. AWS RDS Point-in-Time Recovery (PITR) Procedure
```bash
# 1. Identify target recovery timestamp (ISO-8601 UTC)
RESTORE_TIME="2026-10-12T14:30:00Z"

# 2. Restore DB cluster/instance to new target identifier
aws rds restore-db-instance-to-point-in-time \
  --source-db-instance-identifier merqent-production-primary \
  --target-db-instance-identifier merqent-production-restored \
  --restore-time "${RESTORE_TIME}" \
  --db-subnet-group-name merqent-vpc-db-subnets \
  --vpc-security-group-ids sg-merqent-db-access \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/merqent-db-key

# 3. Wait for instance availability
aws rds wait db-instance-available --db-instance-identifier merqent-production-restored

# 4. Verify restored extensions & migration tables
# 5. Update application configuration DATABASE_URL in AWS Secrets Manager
```

### B. Manual Logical Backup & Disaster Recovery Procedure
```bash
# 1. Create compressed custom archive
pg_dump -h "${DB_HOST}" -p "${DB_PORT}" -U "${DB_USER}" -d "${DB_NAME}" \
  --format=custom --file=merqent_backup_$(date +%Y%m%d_%H%M%S).dump

# 2. Encrypt archive using OpenSSL or AWS KMS before offsite transmission
openssl enc -aes-256-cbc -salt -in merqent_backup.dump -out merqent_backup.dump.enc

# 3. Restore into freshly provisioned database with initialized extensions
pg_restore -h "${TARGET_HOST}" -p "${TARGET_PORT}" -U "${DB_USER}" -d "${TARGET_DB}" \
  --clean --if-exists --no-owner merqent_backup.dump
```
