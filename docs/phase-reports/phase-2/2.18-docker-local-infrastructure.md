## 2. Infrastructure Architecture & Container Orchestration

### 2.1 Service Topology & Local Port Bindings

The platform defines two orchestrated Docker Compose configurations:

1. **Development Composition (`infrastructure/docker/docker-compose.yml`)**:
   Provides backing data and storage infrastructure so engineers can run Next.js and NestJS directly on the host using `pnpm dev` with hot module reloading while connecting to containerized services.
2. **Production Composition (`infrastructure/docker/docker-compose.prod.yml`)**:
   Full containerized stack running Next.js Web, NestJS API, PostgreSQL + pgvector, Redis, and MinIO within an isolated internal bridge network (`merqent-internal`).

### 2.2 Chainguard Hardened MinIO Migration
Due to MinIO's October 2025 upstream distribution policy transition (which removed official pre-built community tags from Docker Hub and resulted in `pull access denied`), the MinIO service was migrated to Chainguard's enterprise-hardened, zero-CVE image `cgr.dev/chainguard/minio:latest`.
- The Chainguard image bundles both the MinIO server binary (`/usr/bin/minio`) and the client utility (`/usr/bin/mc`), enabling built-in health checks (`/usr/bin/mc ready local`) and automated startup bucket provisioning without third-party tools.
- Health-gated one-shot container `merqent_minio_init` waits for `minio: condition: service_healthy`, configures the local alias, and executes `mc mb --ignore-existing local/merqent-secure-documents`.

### 2.3 Multi-Stage Non-Root Production Dockerfiles

Both `infrastructure/docker/Dockerfile.api` and `infrastructure/docker/Dockerfile.web` follow secure multi-stage build patterns:

1. **`Dockerfile.api`**:
   - **Base stage**: `node:20-alpine` with `libc6-compat`, `openssl`, and `pnpm@9`.
   - **Builder stage**: Copies monorepo configuration (`pnpm-lock.yaml`, `pnpm-workspace.yaml`, `turbo.json`), all package definitions, and source files. Builds shared packages (`@merqent/shared-types`, `@merqent/validation`, `@merqent/config`) and compiles NestJS via `pnpm --filter @merqent/api build`.
   - **Runner stage**: Minimal runtime image with system group `nodejs` (GID 1001) and system user `nestjs` (UID 1001). Drops root privileges before exposing port 4000 and executes `node apps/api/dist/main.js`.
2. **`Dockerfile.web`**:
   - **Base stage**: `node:20-alpine` with `libc6-compat` and `pnpm@9`.
   - **Builder stage**: Resolves monorepo workspace dependencies, compiles shared types, validation schemas, and UI components, and builds the Next.js standalone application (`next build`).
   - **Runner stage**: Minimal runtime image with system user `nextjs` (UID 1001), non-root execution, `NEXT_TELEMETRY_DISABLED=1`, and optimized static asset serving.
   - **Vulnerability Neutralization**: Running the Next.js frontend inside Linux containers (`node:20-alpine`) neutralizes the Windows path-handling RCE vulnerability (`GHSA-p293-qw3h-jr36` / CVE-2026-75604).

## 3. Secret Management & Build Isolation

### 3.1 Container Build Leak Prevention (`.dockerignore`)
A repository-root `.dockerignore` file was established to ensure that no developer artifacts, host secrets, or Windows binaries leak into container layers:
- Excludes `.env`, `.env.*` (except `.env.example`).
- Excludes host `node_modules` across the entire workspace tree (`**/node_modules`), preventing Windows-specific symlinks and binaries from breaking Linux container builds.
- Excludes `.git`, `.github`, `.turbo`, `dist`, `.next`, `coverage`, and compiler build caches (`*.tsbuildinfo`).

### 3.2 Environment Verification & Safe Templates
- `.env.example` provides safe default values for local development with placeholder secrets.
- `pnpm env:validate` (`scripts/validate-env.js`) validates all local environment variables against the strict Zod schema before service startup.

## 4. Database Lifecycle, Migrations & Safe Reset Procedures

### 4.1 Extension Initialization
PostgreSQL extension provisioning is managed declaratively via `infrastructure/database/init.sql`:
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pg_trgm";
CREATE EXTENSION IF NOT EXISTS "vector";
GRANT ALL ON SCHEMA public TO merqent_user;
```
When `merqent_postgres` initializes a fresh data volume, Docker executes `init.sql` automatically.

### 4.2 Repeatable Migration & Seeding
Prisma migrations and canonical taxonomy seeding are executed non-destructively:
- Status check: `pnpm prisma:status`
- Safe deployment: `pnpm prisma:migrate` (runs `prisma migrate deploy`)
- Canonical seed: `pnpm prisma:seed`

### 4.3 Guarded Safe Database Reset
Destructive database resets are strictly isolated and guarded:
- PowerShell script: `scripts/database/reset-db.ps1`
- POSIX Bash script: `scripts/database/reset-db.sh`
- Both scripts require explicit confirmation (`-Force`, `--force`, or typing `YES`) before resetting the schema, preventing accidental data loss in local environments.
