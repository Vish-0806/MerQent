## 1. Executive Summary

Task 2.10 establishes a unified, predictable, and strongly-typed API contract and error architecture across the NestJS API (`apps/api`), the Next.js frontend (`apps/web`), and shared workspace packages (`@merqent/shared-types`). 

This architecture guarantees:
- **Canonical Envelope Standardization**: Consistent success envelopes (`ApiResponse<T>` and `PaginatedResponse<T>`) stamped with ISO timestamps and standardized pagination metadata.
- **Predictable, Machine-Readable Errors**: Introduction of canonical `ErrorCode` enums and structured `ApiErrorDetail` arrays, enabling deterministic frontend handling, form validation binding, and automated alerting.
- **Zero Information Leakage in Production**: The global `AllExceptionsFilter` strictly catches unhandled exceptions, logs detailed diagnostic stack traces to the server logger with correlation IDs, and returns sanitized, generic `500 Internal Server Error` responses to clients without exposing internal database statements, stack traces, or credentials.
- **Granular Validation Errors**: Both NestJS `ValidationPipe` (class-validator) and `ZodValidationPipe` produce standardized `VALIDATION_ERROR` payloads with field-level constraint paths and codes.
- **Typed Frontend Client**: The Next.js `ApiClient` maps API error envelopes to `ApiClientError`, exposing convenient status helpers (`isUnauthorized()`, `isForbidden()`, `isValidationError()`, `isServerError()`) and `getFieldErrors()` for form binding.

## 2. API Contract Specification

### 2.1 Success Response Envelope (`ApiResponse<T>`)

Every non-bypassed endpoint is intercepted by `TransformInterceptor` and enveloped into:

```typescript
export interface ApiResponse<T = unknown> {
  data: T;
  meta?: PaginationMeta;
  message?: string;
  timestamp: string; // ISO 8601 UTC
}
```

#### Example GET `/api/v1/auth/me` Response:
```json
{
  "data": {
    "id": "7f000001-926f-40e1-b4f0-4560a8a72b01",
    "email": "pmi.lead@example.com",
    "fullName": "Operating Partner",
    "role": "CONSULTANT_OPERATOR",
    "status": "ACTIVE"
  },
  "timestamp": "2026-10-09T21:10:00.000Z"
}
```

### 2.2 Paginated Response Envelope (`PaginatedResponse<T>`)

List endpoints with pagination return item arrays along with accurate mathematical bounds:

```typescript
export interface PaginationMeta {
  total: number;
  page: number;
  limit: number;
  totalPages: number;
  hasNextPage?: boolean;
  hasPreviousPage?: boolean;
}

export interface PaginatedResponse<T> {
  data: T[];
  meta: PaginationMeta;
  message?: string;
  timestamp: string;
}
```

#### Example GET `/api/v1/projects?page=2&limit=10` Response:
```json
{
  "data": [
    { "id": "proj-11", "title": "Carve-out ERP Migration" },
    { "id": "proj-12", "title": "Supply Chain Integration" }
  ],
  "meta": {
    "total": 55,
    "page": 2,
    "limit": 10,
    "totalPages": 6,
    "hasNextPage": true,
    "hasPreviousPage": true
  },
  "timestamp": "2026-10-09T21:10:00.000Z"
}
```

### 2.3 Standard Error Response Envelope (`ApiErrorResponse`)

```typescript
export interface ApiErrorResponse {
  statusCode: number;
  errorCode?: ErrorCode | string;
  error: string;
  message: string | string[];
  path?: string;
  correlationId?: string;
  timestamp: string;
  details?: ApiErrorDetail[];
}

export interface ApiErrorDetail {
  field?: string;
  message: string;
  code?: string;
}
```

#### Canonical Error Codes (`ErrorCode`):
| Code | HTTP Status | Description |
| :--- | :---: | :--- |
| `VALIDATION_ERROR` | 400 | DTO or schema validation constraint violations |
| `BAD_REQUEST` | 400 | Malformed request syntax or unprocessable parameters |
| `FOREIGN_KEY_VIOLATION` | 400 | Database foreign key integrity constraint violation |
| `UNAUTHORIZED` | 401 | Missing, malformed, or invalid bearer token |
| `INVALID_CREDENTIALS` | 401 | Incorrect password or unrecognized email |
| `TOKEN_EXPIRED` | 401 | JWT access or refresh token has expired |
| `TOKEN_INVALID` | 401 | Token signature verification failed or revoked token presented |
| `FORBIDDEN` | 403 | Authenticated user lacks permission or access rights |
| `INSUFFICIENT_PERMISSIONS` | 403 | User role lacks specific required permission |
| `TENANT_ACCESS_DENIED` | 403 | Request targets an organization outside the user's tenant |
| `ACCOUNT_SUSPENDED` | 403 | User account is suspended |
| `NOT_FOUND` | 404 | Target endpoint or entity not found |
| `RECORD_NOT_FOUND` | 404 | Database entity matching query criteria does not exist |
| `CONFLICT` | 409 | Resource state collision |
| `UNIQUE_CONSTRAINT_VIOLATION`| 409 | Unique constraint violation (e.g. duplicate email) |
| `RATE_LIMIT_EXCEEDED` | 429 | Rate limit threshold reached |
| `INTERNAL_SERVER_ERROR` | 500 | Unhandled internal exception; details logged with correlation ID |
| `SERVICE_UNAVAILABLE` | 503 | Dependency health check failure |

#### Example Validation Error (`400 Bad Request`):
```json
{
  "statusCode": 400,
  "errorCode": "VALIDATION_ERROR",
  "error": "Bad Request",
  "message": [
    "email: Must be a valid email address",
    "password: Password must be at least 8 characters long"
  ],
  "path": "/api/v1/auth/register",
  "correlationId": "b5f2cfcf-9c6f-40e1-b4f0-4560a8a72b01",
  "timestamp": "2026-10-09T21:10:00.000Z",
  "details": [
    {
      "field": "email",
      "message": "Must be a valid email address",
      "code": "isEmail"
    },
    {
      "field": "password",
      "message": "Password must be at least 8 characters long",
      "code": "minLength"
    }
  ]
}
```

#### Example Production 500 Error (Stack Trace Masked):
```json
{
  "statusCode": 500,
  "errorCode": "INTERNAL_SERVER_ERROR",
  "error": "Internal Server Error",
  "message": "Internal server error",
  "path": "/api/v1/matching/run",
  "correlationId": "8f309a12-683a-4efb-88a2-282e389df001",
  "timestamp": "2026-10-09T21:10:00.000Z"
}
```
