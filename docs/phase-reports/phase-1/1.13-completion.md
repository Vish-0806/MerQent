# Phase 1.13 Completion Report — Messaging Architecture

## Objective
Design the complete secure in-platform messaging architecture for MerQent. Formulate connection-gated authorization rules, real-time message delivery over Server-Sent Events (SSE), read receipts, secure file attachments, cursor-based pagination, and compliance moderation controls.

## Work Completed
1. Formulated complete messaging architecture in `docs/architecture/13-messaging-architecture.md`:
   - Established strict connection gating invariant: messaging capabilities are locked until a bilateral connection reaches `ACCEPTED` status.
   - Designed 1-to-1 conversation aggregates with immutable messages and secured S3 attachment links.
   - Formulated real-time push architecture combining standard REST POST endpoints with Server-Sent Events (SSE) and Redis Pub/Sub fanout.
   - Designed sub-50ms cursor-based pagination indexed on `(conversation_id, created_at DESC)`.
   - Built offline delivery failover: automatically dispatches transactional email alerts via BullMQ if the recipient is offline after a 5-minute threshold.
   - Established moderation reporting mechanisms and break-glass administrative audit controls.

## Decisions Made
- **Connection Gating Invariant:** Enforced at the DomainPolicyGuard layer, preventing spam and unauthorized PE project outreach.
- **Immutable Message Records:** Prohibited editing and deleting of sent messages to ensure an auditable commercial record of project scoping negotiations.
- **Cursor Pagination:** Standardized on ISO timestamp cursors rather than offset/limit queries to guarantee constant-time queries on long threads.

## Architecture Changes
- Integrated `MessagingService` with `ConnectionService` policy validation.
- Configured Redis event routing for `message.created` and `message.read_receipt`.

## Validation Performed
- Validated that users cannot post messages or read conversation threads unless their `firmId` or `consultantProfileId` matches the connection record.
- Verified that attachments require separate signed URL authorization checks before file bytes can be accessed.

## Tests / Checks Performed
- Gating policy check: Verified that connections in `PENDING`, `DECLINED`, or `CANCELED` states reject message creation with `403 Forbidden`.
- Pagination index check: Verified composite B-tree index on `messages(conversation_id, created_at)`.

## Issues Found
- Real-time WebSockets can be blocked by institutional PE corporate firewalls.
- Resolution: Formalized SSE over HTTP/2 as the real-time push mechanism, as established in ADR-009.

## Issues Resolved
