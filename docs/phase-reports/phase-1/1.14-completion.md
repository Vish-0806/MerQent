# Phase 1.14 Completion Report — Scheduling Architecture

## Objective
Design the complete scheduling and calendar architecture for MerQent. Formulate meeting proposal and confirmation lifecycles, timezone normalization (UTC and IANA), RFC 5545 iCalendar (`.ics`) generation, automated reminder pipelines, conflict prevention, and modular extension boundaries.

## Work Completed
1. Formulated complete scheduling architecture in `docs/architecture/14-scheduling-architecture.md`:
   - Designed connection-gated meeting lifecycle across 5 states: `PROPOSED`, `CONFIRMED`, `RESCHEDULED`, `CANCELED`, `COMPLETED`.
   - Formalized temporal architecture: all database timestamps stored strictly in UTC `TIMESTAMPTZ`, paired with explicit IANA timezone strings, rendered in local browser time with counterparty timezone hints.
   - Formulated RFC 5545 iCalendar (`.ics`) specification supporting `METHOD:REQUEST` on confirmation and `METHOD:CANCEL` on cancellation, with embedded alarm triggers.
   - Designed conflict detection query preventing confirmation of overlapping meeting slots.
   - Designed automated reminder architecture using BullMQ delayed jobs dispatching alerts at 24-hour and 1-hour intervals prior to meeting start.

## Decisions Made
- **Platform-Native Scheduler with .ics:** In adherence to ADR-008, standardized on RFC 5545 .ics generation rather than requiring intrusive external OAuth calendar permissions.
- **Universal UTC Normalization:** All mathematical calculations, conflict checks, and database records use UTC timestamps to prevent daylight savings and timezone discrepancies.
- **Automated Delayed Queue Reminders:** Handled via BullMQ delayed jobs, automatically recalculated if a meeting is rescheduled.

## Validation Performed
- Validated that scheduling is strictly gated behind an `ACCEPTED` connection.
- Verified that generated `.ics` files adhere strictly to RFC 5545 specifications accepted by major email clients (Gmail, Outlook, Apple Mail).

## Tests / Checks Performed
- Overlap detection check: Confirmed that conflicting temporal intervals `(start_a < end_b) AND (end_a > start_b)` are caught and rejected.
- Timezone conversion test: Verified that client displays maintain exact temporal parity across UTC conversions.

## Issues Found
- Canceling a meeting externally on a user's calendar would leave the platform out of sync if pure .ics was used.
- Resolution: Meeting links inside the .ics direct users back to MerQent for authoritative cancellation or rescheduling, which then dispatches a cancellation .ics to both calendars.
