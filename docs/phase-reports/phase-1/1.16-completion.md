# Phase 1.16 Completion Report — File & Document Architecture

## Objective
Design the complete secure file and document storage architecture for MerQent. Formulate zero-proxy direct S3 uploads/downloads via short-lived signed URLs (TTL <= 15 minutes), strict MIME type and file size whitelisting, asynchronous malware scanning pipelines (ClamAV via BullMQ), SSE-KMS encryption, and fine-grained domain authorization policies.

## Work Completed
1. Formulated complete file architecture in `docs/architecture/16-file-document-architecture.md`:
   - Designed 2-step pre-signed upload workflow: Request Signed PUT URL → Direct S3 Upload → Confirm Upload & Trigger Scan.
   - Formulated authorized direct download flow generating pre-signed GET URLs only after domain policy validation.
   - Formalized `FileRecord` metadata entity in PostgreSQL with cryptographically random storage keys (`vault/{scope}/{uuid}.enc`).
   - Defined strict MIME whitelists across Resumes, Verification Evidence, Project Briefs, and Chat Attachments (max size 25MB; executables strictly prohibited).
   - Designed asynchronous virus scanning pipeline with BullMQ (`file-scan-queue`) and ClamAV; downloads blocked until `scan_status == 'CLEAN'`.
   - Formulated encryption standards: SSE-KMS at rest, TLS 1.3 in transit, and automated 30-day purge lifecycles.
   - Defined domain-level access control rules isolating raw verification evidence from PE firm view.

## Decisions Made
- **Zero-Proxy Signed Storage:** Offloads heavy byte streaming directly to AWS S3 / MinIO, keeping backend API servers fast, stateless, and immune to memory exhaustion.
- **Pre-Signed Download TTL:** Set to 15 minutes, preventing leaked URLs from providing permanent unauthorized access.
- **Pre-Signed Upload Constraint:** Signed PUT URLs enforce exact `Content-Type` and `Content-Length` headers generated during the initial API handshake.

## Validation Performed
- Validated that private consultant verification evidence (e.g., government IDs, unredacted contracts) is inaccessible to PE users even if they obtain a valid file UUID.
- Verified that files flagged as `INFECTED` are immediately purged from S3 storage and blocked from download.

## Tests / Checks Performed
- MIME security check: Verified that dangerous MIME types (`application/x-sh`, `application/x-msdownload`, `.exe`, `.bat`) are blocked.
- Path traversal verification: Confirmed that object keys use system UUIDs, making path traversal (`../`) impossible.

## Issues Found
- Direct client uploads could leave orphaned S3 objects if the client fails to invoke the confirmation endpoint.
- Resolution: S3 bucket lifecycle rule automatically purges unconfirmed multi-part uploads and incomplete objects older than 24 hours.

## Issues Resolved
- Storage leak resilience achieved.

## Risks
